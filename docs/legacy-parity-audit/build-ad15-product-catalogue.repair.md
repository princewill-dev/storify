# AD-15 — Product & Category Catalogue (WS15) — repair report

Scope: the files the implementation reported — `storify-api` (`Admin\ProductController`, `Admin\CategoryController`, `Admin\Concerns\SerializesAdminProducts`, `routes/api/v1/admin/ad15-product-catalogue.php`, `tests/Feature/Api/ad15productcatalogueTest.php`) and `storify-admin` (api/router/nav modules, the three catalogue views and the ad15 category modal). No management-repo files involved.

Commands run: `php -l` on all five PHP files; `php artisan route:list --path=api/v1/admin`; a scripted duplicate route-name/URI scan of the full route table; a booted-app reflection check of every route target; a booted-app serializer smoke test; read-only SFC/TS parsing of the SPA files with the repo's own `@vue/compiler-sfc` and `typescript`. `php artisan test` / `npm run typecheck` were NOT run (fleet rule).

## Fixes applied

1. **`SerializesAdminProducts::decimalToMoney()` did not exist — fatal on every endpoint.** The trait calls `$this->decimalToMoney(...)` for the product `amount` (line 69) and each variant `amount` (line 130) but never defined it, so every list row, detail payload and mutation echo raised `Call to undefined method ...::decimalToMoney()` — all 14 WS15 routes would 500. Added the method: the stored decimal passed through as a naira float (`(float)`, `null` preserved), which is exactly what the management payload emits (`'amount' => (float) $product->amount`) and what the SPA round-trips (list/detail `formatMoney`, the edit form's `amount` field). All money arithmetic in the trait still runs on integer minor units via `minorUnits()`/`minorToMoney()`; the docblock states this.
2. **`ProductController::update()` wiped bulk pricing on every partial update.** `bulk_quantity`/`bulk_price` were written unconditionally (`filled(...) ? value : null`), so any payload that did not mention them — e.g. a variants-only update — silently nulled the stored bulk pricing. They are now only written when the payload carries either key (present-but-empty still clears, which is what the SPA's `blankFields` sends and what legacy's form did). This matches the method's own "only write what the payload carries" rule already applied to the flags.
3. **Test file: four assertions could never pass (`assertSame` int-vs-float).** PHP's JSON encoder drops the zero fraction for integral floats (verified through `response()->json()` in the booted app: `['x' => 1500.0]` serialises as `{"x":1500}`), so `final_amount`, `variant_price.min`, `variant_price.max` and `cost_price` decode as ints. The three Pest `->toBe(x.0)` chains now cast the decoded value to `(float)` first, and `assertJsonPath('data.product.cost_price', 400.0)` uses the suite's established closure form (`fn ($value) => (float) $value === 400.0`).
4. **Test file: the bulk-clearing test proved nothing.** It seeded `bulk_quantity`/`bulk_price` through `Product::create`, which silently drops them (both are absent from `Product::$fillable` — WS-14's migration added the columns, not the model). It now persists the start state with `forceFill([...])->save()`, asserts the clearing update really nulls the pair, and adds a partial-update case proving unmentioned bulk pricing survives (the fix in item 2).

## Checklist results

1. **Route → method mapping — PASS.** Reflection against the booted app: every one of the 14 registrations resolves to an existing public method with parameters matching the URI (`index`, `formOptions`, `store`, `show`, `update`, `updateStatus`, `destroy`, `storeIndex`, `showInStore` on `ProductController`; `index`, `store`, `update`, `destroy`, `storeIndex` on `CategoryController`). `storeIndex`/`showInStore` take `Store $store` (bound by the public `store_id`) and the raw `string $product` code; `{product}` binds `Product` by `product_code`, `{category}` by id.
2. **Envelope + scoping — PASS.** Every public method returns `$this->ok($data, $message, $status, $meta)` or `$this->error(...)`; the only other exits are the house `abort_unless(403)` platform-role guard (`EnsuresPlatformAdmin`, on every method) and two `abort(422, …)` refusals inside private transaction helpers, whose `{message}` body matches the `error()` shape. This is a **platform-wide** admin surface by design (roadmap §18), so "tenant scoping" is the platform-role guard plus re-checking every request id against the database: `liveStore()` for `store_id` (deleted stores refused), `categoryMismatch()` (a category must belong to the chosen store), variant-ownership check in `syncVariants()`, image-ownership check in `storeImages()`, and the store-scoped show looking the code up inside the store. `DB::transaction` wraps create/update/status/delete on both controllers.
3. **SPA calls ↔ routes ↔ api module — PASS.** All 14 client paths in `api/modules/ad15-product-catalogue.ts` map to registered routes (including the multipart `_method=PUT` spoof for edit); every call a view makes (`productCatalogueApi.list/show/form-options/create/update/updateStatus/remove`, `categoryCatalogueApi.list/create/update/remove`) is exported by that module and points at a live route. The WS-6 store console's `router.hasRoute()` probes (`products`, `products.create`, `categories`, `categories.create`) and its `?store_id=` deep links resolve.
4. **Route module hygiene — PASS.** No prefix/name/auth wrapper; the only group is the module-local `permission:admin.products` + `AdminApiActivityLogger` pair, the same idiom as `ad01`/`ad14`, and it is required (the parent group cannot know each module's permission). No duplicate route names or URIs anywhere in the route table; `form-options` sits before the `{product}` wildcard (and static segments outrank parameters regardless).
5. **Router/nav module shapes — PASS.** `router/modules/ad15-product-catalogue.ts` default-exports `RouteRecordRaw[]` (children of `/`, no leading slash, `meta.title` on each; names `products`, `products.create`, `products.show`, `products.edit`, `categories`, `categories.create` — no collisions with other modules). `nav/modules/ad15-product-catalogue.ts` default-exports `Array<{ label, nodes }>` with the `icon`/`to`/`permission` node shape `AdminLayout.vue` globs.
6. **Imports — PASS.** Every `@/…`/relative import in the views, component and modules resolves to an existing file; every named export used exists; all PHP `use` targets exist. SFC template + script blocks and the TS modules parse clean with the repo's own compiler.
7. **PHP syntax — PASS.** `php -l` clean on all five files; `route:list` shows the 14 WS15 routes with the inherited auth/audience/team middleware plus the module gates.

Also verified beyond the checklist: serializer output reproduces the legacy price strings exactly (`₦1,000.00 -> ₦900.00 (-10%)`, `₦1,500.00 - ₦1,700.00`); `ActivityRecorder::record()` and `StockLedgerService::recordAddition()` are called with matching signatures; `stock_locations` has no unique index that `firstOrCreate` could trip; the seeder gives `Platform Admin`/Super Admin `admin.products` and withholds it from `Finance Admin` (the tests' permission expectations hold); no `vendor` naming anywhere in the reported files.
